第7章 GitHubで公開

作ったサイトをインターネットに公開します。同時に、現場必須ツール「Git / GitHub」に入門します。

さくらちゃん Gitは今やWeb系に限らずほぼ全ての開発現場で使われる必須ツールです。 「常駐先で急にGitを使うことになった」はSESあるあるなので、この機会に基本操作を体に入れておきましょう。 おまけに、GitHubには無料でWebサイトを公開できる機能まで付いてくるんです!

7-1. Gitとは:セーブポイントを作れる仕組み 基礎

Gitは「バージョン管理システム」。ファイルの変更履歴をセーブポイント(コミット)として記録し、いつでも過去の状態に戻れるようにする仕組みです。

  • 「動いていたのに、どこかいじったら壊れた」→ 直前のコミットに戻せる
  • 「誰がいつ何を変えたか」→ 履歴が全部残る
  • 複数人で同じファイルを編集しても、変更を合流(マージ)できる

GitHubは、Gitの履歴(リポジトリ)をインターネット上に置けるサービスです。バックアップ・共有・公開の拠点になります。

用語意味
リポジトリプロジェクト一式+全履歴が入った保管庫
コミット変更のセーブポイント。「何を変えたか」のメッセージ付き
プッシュ手元のコミットをGitHubへ送ること
クローンGitHub上のリポジトリを手元に複製すること
ブランチ履歴の分岐。本流(main)を壊さず作業するための並行世界

7-2. 準備:インストールとアカウント作成 基礎

  1. Gitのインストール … git-scm.com からダウンロード(設定は基本すべてデフォルトでOK)
  2. GitHubアカウント作成 … github.com で無料登録(ユーザー名は公開URLの一部になるので真面目なものを!)
  3. 初期設定 … VS Codeのターミナル(Ctrl + @)で自分の名前とメールを登録 
    git config --global user.name "Taro Yamada"
git config --global user.email "yamada@example.com"

7-3. 最初のコミットからプッシュまで 全員

総合演習で作ったsakura-techフォルダを公開してみましょう。VS Codeでフォルダを開き、ターミナルで以下を1行ずつ実行します。

ターミナル(フォルダの中で実行) 
# ① このフォルダをGit管理下に置く(最初の1回だけ)
git init

# ② 全ファイルをコミット対象に載せる(ステージング)
git add .

# ③ セーブポイントを作る(-m の後はメッセージ)
git commit -m "コーポレートサイト初版"

次に、GitHub側で受け皿を作ります。

  1. GitHubにログイン → 右上の「+」→「New repository」
  2. Repository name に sakura-tech と入力、Public を選択して「Create repository」
  3. 作成後に表示されるコマンドの「…or push an existing repository」の3行を、そのままターミナルで実行: 
    git remote add origin https://github.com/あなたのID/sakura-tech.git
git branch -M main
git push -u origin main

ブラウザでGitHubのリポジトリページを再読み込みして、ファイルが表示されていれば成功です🎉

💡 2回目以降の更新は3コマンドだけ
ファイルを修正したら git add . → git commit -m "変更内容" → git push。この3つのリズムを体で覚えましょう。 VS Codeの左側の「ソース管理」パネルから、ボタン操作で同じことをすることもできます。

7-4. GitHub Pagesで世界に公開 全員

いよいよ公開です。追加費用ゼロ、設定は3クリックです。

  1. GitHubのリポジトリページで「Settings」タブを開く
  2. 左メニューの「Pages」をクリック
  3. 「Branch」で main を選び「Save」

1〜2分待つと、次のURLであなたのサイトが世界中から見られる状態になります。

https://あなたのID.github.io/sakura-tech/
⚠️ 公開前チェック
Publicリポジトリは世界中の誰でも中身を見られます。本名・住所・社外秘情報・パスワードやAPIキーを含むファイルは絶対にコミットしないこと。 これは研修を超えて、実務での重大事故(秘密情報のコミット漏洩)防止の鉄則です。一度プッシュした秘密情報は「削除しても履歴に残る」ことも覚えておいてください。

7-5. 現場で使うGitの一歩先 全員

チーム開発では、mainブランチに直接プッシュせず、次の流れで進むのが一般的です(GitHub Flow)。

① git switch -c feature/add-news   ← 作業用ブランチを切る
② 作業してコミット
③ git push -u origin feature/add-news
④ GitHub上で「Pull Request(PR)」を作成 ← 「この変更を取り込んでください」という依頼
⑤ チームメンバーがコードレビュー
⑥ 承認されたらmainにマージ

「PR」「レビュー」「マージ」は現場の日常会話です。言葉だけでも今日覚えて帰ってください。

🎓 ベテラン向けコラム:公開・運用の選択肢 ベテラン向け
  • 静的ホスティングの選択肢 … GitHub Pagesの他、Cloudflare Pages、Netlify、Vercelが定番。いずれも無料枠があり、Gitにプッシュすると自動でビルド・デプロイされる(CD:継続的デプロイ)
  • GitHub Actions … プッシュを起点にテストやビルドを自動実行するCI/CD基盤。Pagesのデプロイも実は内部でActionsが動いている
  • 独自ドメイン … お名前.comなどで取得したドメインをGitHub Pagesに設定可能(CNAMEレコード+リポジトリ設定)。HTTPSも自動で有効化される
  • 会社案件での注意 … 無料ホスティングのSLA(稼働保証)は基本なし。商用案件では要件に応じてクラウド(AWS S3+CloudFront等)や有料プランを検討する
