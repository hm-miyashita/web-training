第4章 レイアウトとレスポンシブ

要素を「横に並べる」「格子状に配置する」——ページの設計図を自在に描く技術を学びます。

さくらちゃん 昔は「要素を横に並べる」だけで一苦労だったんです(floatという茨の道がありました…)。 でも今はFlexboxとGridという2つの強力な道具があります。ベテランの方、float時代の知識は一度忘れてください!今はもっとシンプルです🌸

4-1. Flexbox:一方向に並べる 全員

親要素にdisplay: flex;と書くだけで、子要素が横一列に並びます。「並べる方向は1方向(横 or 縦)」なのがFlexboxの特徴です。

かつて難問だった「要素を画面中央に置く」は、Flexboxならこの3行です。丸暗記推奨!
display: flex; justify-content: center; align-items: center;

4-2. Grid:格子状に並べる 全員

Flexboxが「1方向の列」なら、Gridは「行と列の表(格子)」でレイアウトします。カード一覧や、ページ全体の骨格づくりが得意です。

grid-template-columns: 1fr 1fr 1fr; の fr は「fraction(分数)」の意味で、「余った幅を1:1:1で分ける」という指定です。240px 1frと書けば「左は固定240px、右は残り全部」という、サイドバー付きレイアウトになります(この教材サイトがまさにその構造です)。

FlexboxとGridの使い分け

FlexboxGrid
得意な形1方向の並び(ナビメニュー、ボタン列)2次元の格子(カード一覧、ページ全体の骨格)
発想中身のサイズに合わせて流す先に枠を決めて中身を流し込む
迷ったら「行も列も意識する」ならGrid、それ以外はFlexboxでOK

4-3. レスポンシブデザイン 全員

日本のWebアクセスの約7割はスマートフォンです。PCでもスマホでも見やすいページにする技術がレスポンシブデザインで、柱は2つあります。

① viewportメタタグ(おまじないではなく必須設定)

<meta name="viewport" content="width=device-width, initial-scale=1.0">

これをheadに書かないと、スマホは「PC用の画面を縮小表示」してしまい、文字が豆粒になります。書き忘れ事故が非常に多いので、HTMLの雛形に必ず含めましょう。

② メディアクエリ:画面幅で条件分岐

/* 通常(PC)のスタイル */
.cards {
  display: grid;
  grid-template-columns: 1fr 1fr 1fr;  /* PCでは3列 */
}

/* 画面幅が600px以下のとき、上書きする */
@media (max-width: 600px) {
  .cards {
    grid-template-columns: 1fr;        /* スマホでは1列 */
  }
}

切り替えの境界値(ブレークポイント)は、600px前後(スマホ)と1000px前後(タブレット)がよく使われます。

💡 DevToolsでスマホ表示を確認
F12 → 左上のスマホ/タブレットアイコン(デバイスツールバー)をクリックすると、各種スマホの画面サイズで表示確認ができます。 実機がなくても開発できるのはこの機能のおかげ。このページを今すぐスマホ表示にしてみましょう——サイドバーが上に回り込み、1カラムに変わります。それがまさにメディアクエリの仕事です。

値動き使いどころ
static通常の流れ(初期値)—
relative本来の位置から相対的にずらす/absoluteの基準になる微調整、基準づくり

🎓 ベテラン向けコラム:メディアクエリ一辺倒からの脱却 ベテラン向け

レスポンシブの手法はここ数年で大きく進化しました。キャッチアップの要点は3つです。

  • コンテナクエリ(@container) … 「画面幅」ではなく「親要素の幅」で分岐できる。コンポーネント単位の設計と相性が良く、全モダンブラウザ対応済み。「サイドバーに置いても本文に置いても勝手に最適化されるカード」が実現可能に
  • clamp()による流体デザイン … font-size: clamp(1rem, 2.5vw, 1.5rem); のように最小・推奨・最大を1行で書き、ブレークポイントなしで滑らかにサイズが変わる
  • aspect-ratio、min()/max()、subgrid … 「JSで計算していたレイアウト」がCSSだけで完結する場面が急増。Grid内の入れ子の行揃えはsubgridで解決

「ブレークポイントを何個も書いて微調整」から「そもそも壊れない流体レイアウトを設計する」への発想転換が、モダンCSSの潮流です。
