ページの「骨組み」を作る言語、HTMLを学びます。この章から実際に手を動かします!

さくらちゃん この章には「ライブエディタ」が登場します。左側のコードを書き換えると、右側に結果がすぐ表示されるので、 どんどん書き換えて実験してくださいね。壊しても誰にも迷惑がかからないのが練習環境のいいところです!

2-1. HTMLとタグ 基礎

HTML(HyperText Markup Language)は、文章に「これは見出し」「これは段落」という意味の印(マーク)を付けていく言語です。印付けにはタグを使います。

<h1>こんにちは</h1>
└┬┘           └─┬─┘
開始タグ        終了タグ(スラッシュ付き)

<h1> 〜 </h1> で囲まれた全体を「要素」と呼びます

実際に触ってみましょう。左のコードを編集すると右に即反映されます。

✏️ コード(編集できます)
🖥️ 表示結果

2-2. HTML文書の全体構造 基礎

1つのHTMLファイルは、必ず次の「定型」から始まります。VS Codeで新しいファイルを作り、index.htmlという名前で保存して、以下を打ち込んでみましょう(写経推奨!)。

index.html 
<!DOCTYPE html>                    ←「これはHTML5文書です」という宣言
<html lang="ja">                   ← 文書全体の入れ物(lang="ja"で日本語と明示)
<head>                             ← ページの「設定情報」置き場(画面には出ない)
  <meta charset="UTF-8">           ← 文字コード。これがないと文字化けの原因に!
  <title>私のページ</title>        ← ブラウザのタブに表示されるタイトル
</head>
<body>                             ← 画面に表示される内容はすべてこの中に書く
  <h1>こんにちは!</h1>
</body>
</html>
💡 表示のしかた
保存したindex.htmlをダブルクリックすると、ブラウザで開けます。コードを直したら、上書き保存 → ブラウザでF5(再読み込み)。この繰り返しが開発の基本サイクルです。

2-3. よく使うタグ図鑑 全員

タグ 意味 ポイント
<h1>〜<h6> 見出し(hはheading) h1が最重要。数字は「見た目の大きさ」ではなく「階層」
<p> 段落(paragraph) 文章のかたまりごとに使う
<a> リンク(anchor) href属性で行き先を指定
<img> 画像(image) srcで画像の場所、altで代替テキスト。終了タグ不要
<ul> / <ol> / <li> 箇条書き / 番号付きリスト / 項目 ul=unordered、ol=ordered
<table> / <tr> / <th> / <td> 表 / 行 / 見出しセル / データセル この表もtableタグ製です
<div> / <span> 意味を持たないグループ化用の箱 divはブロック、spanは行内。CSSと組み合わせて使う
<br> 改行 多用は禁物。段落は<p>で分ける

属性:タグへの追加情報

開始タグの中には属性(名前="値"の形)を書けます。

<a href="https://www.google.com">Googleへ</a>
   └────────────┬────────────┘
     href属性:リンクの行き先を指定

<img src="sakura.png" alt="桜のマスコット">
     └──────┬──────┘  └────────┬────────┘
      画像ファイルの場所   画像が表示できない時や
                        音声読み上げで使われる説明文

リンク・画像・リストをライブエディタで試してみましょう。

2-5. セマンティックHTML:意味のある骨組み 全員

なんでも<div>で作ることもできますが、現代のHTMLでは「その部分が何なのか」を意味で表すタグを使うのが正解です。

<body>
  <header>   ← ページ上部(ロゴ、サイト名など)
    <nav>    ← ナビゲーション(メニュー)
  </header>
  <main>     ← そのページの主内容(1ページに1つ)
    <article> ← それ単体で完結する記事
    <section> ← 意味のあるまとまり・区切り
    <aside>   ← 補足・サイドバー
  </main>
  <footer>   ← ページ下部(著作権表示など)
</body>

なぜ意味を持たせるのか?理由は3つあります。

  • 検索エンジン(SEO) … Googleがページの構造を正しく理解できる
  • アクセシビリティ … スクリーンリーダー(音声読み上げ)利用者が「メニューに飛ぶ」「本文に飛ぶ」といった操作をできるようになる
  • 保守性 … 他人(3ヶ月後の自分を含む)がコードを読んだとき、構造がすぐ分かる
🎓 ベテラン向けコラム:divスープからの卒業は終わったか ベテラン向け

セマンティックHTMLの重要性は、近年アクセシビリティ法制の面から再注目されています。日本でも2024年4月施行の改正障害者差別解消法により、民間事業者の合理的配慮が義務化され、公共系・大手企業案件ではWCAG(Web Content Accessibility Guidelines)準拠が要件に明記されるケースが増えました。

また、<dialog>、<details>/<summary>、<search>など「昔はJSで自作していたUI」がHTML標準要素になっています。モーダルをdivとJSで自作する前に、まず標準要素で足りないか確認するのが現代流です。
