第6章 総合演習:コーポレートサイトを0から作る

ここまでの知識を総動員して、架空企業のWebサイトを1人で作り上げます。本章は読む章ではなく「作る章」です。

さくらちゃん 実務のWeb制作は「いきなりコードを書く」のではなく、要件確認 → 設計 → 実装 → 確認の順に進みます。 この演習も同じ流れでやってみましょう。SESの現場でお客様の要件を形にする、あの流れの縮小版です!

STEP 0. 課題の要件(お客様からの依頼書) 全員

📋 依頼書

架空企業「桜テック株式会社」のコーポレートサイトを制作してください。

  • ページ構成:トップページ 1枚(ページ内をスクロールで移動する構成でOK)
  • 必須セクション:①ヒーロー(メインビジュアル) ②会社概要 ③事業内容(3つ) ④お知らせ ⑤お問い合わせフォーム ⑥フッター
  • スマホでもPCでも崩れないこと(レスポンシブ必須)
  • ナビメニューをクリックすると各セクションに移動できること
  • 会社のイメージカラーは自由。ただしサイト全体で統一感を出すこと

STEP 1. 設計:紙に描いてから作る 全員

いきなりVS Codeを開かず、まずワイヤーフレーム(画面の配置図)を紙かメモアプリに描きます。5分でOK。

STEP 2. 実装の手順ガイド 基礎

迷子にならないよう、作る順番を示します。「HTMLを全部書いてからCSS」ではなく、セクションごとに HTML → CSS を繰り返すのがおすすめです。

  1. 雛形 … DOCTYPE〜body、viewportメタタグ、CSS/JSの読み込み(第2章)
  2. セマンティックな骨組み … header / main / footer と、各セクションの<section id="about">など。idを付けるのがポイント(ナビのリンク先になる)
  3. ヘッダーとナビ … <a href="#about">会社概要</a>のようにページ内リンクにする。Flexboxで横並び(第4章)
  4. ヒーロー … キャッチコピーを大きく。background: linear-gradient(...)やパディング大きめで存在感を
  5. 会社概要 … tableで(第2章)
  6. 事業内容 … Gridで3列カード、メディアクエリでスマホ1列(第4章)
  7. お知らせ・フォーム … リストとform(第2章)
  8. JavaScriptで動きを1つ以上 … 下の課題リストから選択(第5章)
  9. スマホ確認 … DevToolsのデバイスツールバーで最終チェック(第4章)
💡 詰まったときの調べ方(これも研修の一部です)
①エラーや疑問をDevToolsで確認 → ②MDN(developer.mozilla.org)で該当プロパティを検索 → ③それでも不明なら教材の該当章に戻る。 「調べて解決する力」こそ、現場で一番評価されるスキルです。生成AIに聞くのも現代の正攻法ですが、出てきたコードを理解してから使うこと。理解せず貼るのはNGです。

STEP 3. レベル別 追加課題 全員

基本要件を満たしたら、自分のレベルに合わせて追加課題に挑戦してください。

🌱 初級(新卒・未経験)

  • ナビメニューにホバー効果を付ける(:hoverで色が変わる)
  • 「トップへ戻る」ボタンを右下に固定表示する(position: fixed)
  • お知らせを1件クリックすると詳細が開閉する(第5章のクラス切替パターン)

🌿 中級(若手〜中堅)

  • スマホ表示のときだけナビを「ハンバーガーメニュー(≡)」にする(メディアクエリ+クラス切替の合わせ技)
  • フォーム送信時にJavaScriptで入力チェックをする(空欄なら警告表示、event.preventDefault()を調べてみよう)
  • スクロールに応じてセクションがふわっと現れる(IntersectionObserverを調べてみよう)

🌸 上級(ベテラン)

  • CSS変数でカラーテーマを定義し、ダークモード切替ボタンを実装する(bodyへのクラス切替+CSS変数の上書き)
  • お知らせをJSの配列データから動的に生成する(HTMLに直書きしない)。余裕があればfetchでJSONファイルから読み込む
  • Lighthouse(DevToolsの監査ツール)でパフォーマンス・アクセシビリティのスコアを測り、両方90点以上にチューニングする
  • コンテナクエリ(@container)を使い、カードコンポーネントを置き場所に応じて自動最適化させる

STEP 4. セルフレビュー(チェックリスト) 全員

完成したら、納品前のつもりで自己点検しましょう。

#チェック項目
1タイトルバー(titleタグ)に適切なサイト名が表示されている
2viewportメタタグがあり、スマホで文字が豆粒にならない
3画像にalt属性がある/見出しはh1→h2→h3の順で飛ばしていない
4divだけでなくheader/main/section/footerで構造化されている
5CSSは外部ファイルで、インラインstyleを使っていない
6色やフォントに統一感がある(CSS変数を使うとなお良い)
7画面幅を縮めても横スクロールが発生しない
8ConsoleタブにJavaScriptエラーが出ていない
9ナビの全リンクが正しいセクションに飛ぶ
10他人が読んで分かるコードになっている(インデント、適切な命名)
さくらちゃん 複数人が同時に待機中なら、お互いのサイトをレビューし合うのがおすすめ! 「レビューする側」に回ると理解度が一気に上がりますし、実務のコードレビューの練習にもなります。 ベテランの方は、若手のコードレビュー役をぜひ買って出てください🌸
📝 成果物の提出

完成したら、次章「GitHubで公開」の手順でリポジトリにアップし、公開URLを研修担当者に共有してください。作って終わりではなく、公開して人に見てもらうまでが本演習です。
