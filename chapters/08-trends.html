第8章 Web業界の最新トレンド(2026年版)

基礎を学んだ皆さんが「現場の会話についていく」ための、いまのWeb業界の見取り図です。

さくらちゃん この章は新卒の方には「地図」として、ベテランの方には「知識の棚卸しリスト」として使ってください。 全部を深く理解する必要はありません。「言葉を知っていて、概要を説明できる」だけで、現場での会話とキャッチアップの速度が全然違いますよ🌸

8-1. フロントエンドフレームワークの世界 全員

実務の中〜大規模開発では、素のHTML/JSではなくフレームワークを使うのが主流です。「部品(コンポーネント)を組み合わせてUIを作る」という発想は全フレームワーク共通です。

名前特徴ひとこと
React 最大シェア。求人数も最多 迷ったらこれ。JSXという記法でUIを書く
Next.js Reactベースのフルスタックフレームワーク 「React案件」の実態はNext.js案件であることが多い
Vue.js 学習しやすく日本で人気。国内SIer案件でも多い HTMLに近い書き心地。Nuxtはそのフルスタック版
Svelte / Astro 新世代。ビルド時に最適化し実行時が軽い Astroはコンテンツサイトで採用増加中
TypeScript JavaScriptに型を足した言語(フレームワークではない) 現場は今やTS前提。JSの次に学ぶべき筆頭
💡 学ぶ順番を間違えない
フレームワークは、この研修でやったHTML/CSS/JSの理解の上に成り立っています。基礎を飛ばしてReactから入ると必ず伸び悩みます。この研修の内容こそが、どのフレームワークにも通じる土台です。

8-2. レンダリング戦略:SSR / SSG / CSR ベテラン向け

「HTMLをいつ・どこで組み立てるか」は、現代フロントエンドの中心的な設計テーマです。

方式組み立てるタイミング向いている用途
CSR(Client Side Rendering)ブラウザ上でJSが組み立てるログイン後の管理画面・業務アプリ
SSR(Server Side Rendering)リクエストのたびにサーバーでECや更新頻度の高いメディア
SSG(Static Site Generation)ビルド時に事前生成コーポレートサイト、ブログ、ドキュメント

近年はこれらを混ぜる(ページ単位・部品単位で使い分ける)のが主流で、React Server Componentsやアイランドアーキテクチャ(Astro)など「必要な部分だけJSを送る」方向に進化しています。皆さんが総合演習で作ったのは、いわば手作りのSSGサイトです。

8-3. アクセシビリティ(a11y):義務の時代へ 全員

アクセシビリティ=「高齢者や障害のある方を含む、誰もが使えること」。日本では2024年の改正障害者差別解消法施行を機に、官公庁・大手案件でWCAG準拠が要件化される流れが加速しています。もはや「余裕があればやる」ものではありません。

今日からできる基本5箇条:

  1. 画像に適切なaltを書く(第2章でやりましたね)
  2. 見出し階層(h1→h2→h3)を飛ばさない
  3. 文字色と背景色のコントラストを確保する(DevToolsで検証可能)
  4. キーボードだけで全操作できるようにする(Tabキーで一周してみる)
  5. 「ここをクリック」ではなく意味の分かるリンクテキストにする

8-4. パフォーマンス:Core Web Vitals ベテラン向け

Googleはページの体感速度をCore Web Vitalsという3指標で計測し、検索順位の要因にしています。

  • LCP(Largest Contentful Paint)… メインコンテンツが表示されるまでの速さ(目標2.5秒以内)
  • INP(Interaction to Next Paint)… 操作への反応の速さ(旧指標FIDから2024年に交代)
  • CLS(Cumulative Layout Shift)… 表示中のガタつき(画像にwidth/height指定を!)

計測はDevToolsのLighthouseタブから誰でも実行できます。総合演習の上級課題でぜひ。

8-5. AIとWeb制作:開発スタイルの地殻変動 全員

この数年で最も大きな変化です。GitHub CopilotやClaude、ChatGPTなどの生成AIは、コード補完から「要件を伝えるとページ一式を生成する」レベルに到達し、AIエージェントに開発タスクを任せるスタイルも実用化しています。

ではこの研修は無駄だったのでしょうか?——むしろ逆です。

  • AIの出力の正否を判断できるのは、基礎がある人だけ。AIは自信満々に間違えます
  • 要件をAIに正確に伝える(プロンプトを書く)には、HTML/CSS/JSの語彙が必要
  • セキュリティ・アクセシビリティ・保守性のレビューは人間の仕事として残る

推奨する使い方:「まず自分で書く → AIにレビュー・改善案を求める → 差分から学ぶ」。写経段階でAIに丸投げすると、成長が止まります。

8-6. セキュリティの基礎知識 全員

フロントエンド担当でも最低限知っておくべき攻撃と対策です。名前だけでも覚えておきましょう。

脅威概要基本対策
XSS(クロスサイトスクリプティング) 入力欄経由で悪意あるスクリプトを埋め込まれる ユーザー入力をそのままHTMLに埋め込まない(textContentを使う等)
CSRF(クロスサイトリクエストフォージェリ) ログイン済みユーザーに意図しない操作をさせる トークン検証(フレームワークが標準装備)
秘密情報の漏洩 APIキー等をフロントのコードやリポジトリに含めてしまう 第7章の鉄則。フロントのJSは全世界に公開されると心得る

8-7. キャッチアップし続けるための情報源 全員

  • MDN Web Docs … Web技術の公式辞書。まずここ(日本語あり)
  • web.dev … Googleによるベストプラクティス集
  • State of JS / State of CSS … 年次の大規模開発者調査。トレンドの定点観測に最適
  • Can I use … ブラウザ対応状況の確認。「Baseline」表示が新しい判断基準に
  • 国内では Zenn / Qiita、カンファレンス動画(YouTube)も有効
